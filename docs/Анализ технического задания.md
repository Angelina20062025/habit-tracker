# 1. Анализ технического задания
Целью данной курсовой работы является разработка веб-приложения 
«Трекер привычек» на фреймворке Spring (Java), представляющего собой 
серверную часть клиент-серверной системы. Приложение предназначено для 
автоматизации процессов формирования и отслеживания полезных привычек, 
ведения справочника типовых привычек, управления пользователями, 
фиксации выполнения привычек, анализа прогресса, формирования сводной 
отчётности и отправки e-mail-уведомлений. Система выступает серверным 
API, с которым взаимодействует мобильный клиент на ОС Android (Kotlin), а 
также веб-интерфейс администратора.

Данная АИС должна предоставлять пользователям функционал в 
зависимости от их роли:

1) Зарегистрированный пользователь должен иметь возможность 
создавать собственные привычки, используя как предоставленный базовый 
список, так и добавляя свои желаемые привычки. Пользователь создаёт 
собственные привычки с указанием цели, периодичности и напоминаний. 
Система предоставляет пользователю наглядную статистику прогресса в 
виде календаря и графиков, а также функцию получения уведомлений-
напоминаний.

2) Администратор реализует управление пользователями и ведёт 
справочник типовых привычек. Взаимодействие с базой данных PostgreSQL 
и кабинетом администратора осуществляется через веб-интерфейс для 
администратора.

Для достижения поставленной цели необходимо реализовать 
следующие ключевые требования:

1) Должен существовать базовый каталог привычек, которые пользователь 
может выбрать для отслеживания (например, «Зарядка», «Чтение 
книг»).

2) Пользователь должен иметь возможность создавать собственные 
привычки со своим названием и описанием.

3) Для каждой привычки, добавленной пользователем, необходимо 
хранить ее параметры: дату начала, частоту выполнения (например, 
ежедневно, раз в неделю), категорию.

4) Необходимо фиксировать историю выполнения привычки: дату и время 
отметки о выполнении, привязанные к конкретной привычке 
конкретного пользователя.

5) Для анализа статистики необходимо хранить данные о текущих сериях 
выполнения – количество периодов подряд, когда привычка 
выполнялась без пропусков.

Ключевыми функциональными требованиями являются:

1) Управление привычками – создание, чтение, обновление, удаление, 
включая выбор из базового списка или создание своей.

2) Отслеживание выполнения – интуитивно понятный интерфейс (в виде 
календаря) для ежедневной отметки о выполнении привычки.

3) Статистика и визуализация – предоставление пользователю данных о 
его успехах, выполненные задания за период, графики прогресса, 
отображение текущей серии и общего количества выполнений.

4) Отправка e-mail-уведомлений-напоминаний о необходимости 
выполнить запланированную привычку.

5) Валидация данных на стороне клиента (на предмет корректности 
формата данных) и на стороне сервера (на предмет соответствия данных 
логике работы).

6) Формирование отчетов в виде Excel таблиц или pdf-файлов.

Для осуществления данных требований потребуется выполнить 
следующие задачи:

1) Описание бизнес-логики и разработка логической модели данных, 
определение всех сущностей, их атрибутов и взаимосвязей.

2) Проектирование архитектуры серверной системы на основе фреймворка 
Spring.

3) Реализация REST API для взаимодействия с мобильным клиентом и веб-
интерфейсом.

4) Реализация механизмов аутентификации и авторизации пользователей с 
разграничением прав по ролям.

5) Реализация модуля формирования отчётов на основе данных из БД.

6) Реализация модуля отправки e-mail-уведомлений.

7) Разработка адаптивного веб-интерфейса (шаблонизатор Thymeleaf) для 
кабинета администратора.

8) Написание модульных тестов для бизнес-логики проекта.

9) Тестирование разработанной АИС.

Потребности потенциального пользователя заключаются в:

1) Простоте и скорости фиксации результатов, возможности отметить 
выполнение привычки в один клик.

2) Визуальном отображении успехов (графики, календари), чтобы 
мотивировать продолжать освоение привычки.

3) Возможности задать удобный график для каждой привычки.

4) Получении уведомлений, чтобы не забывать о запланированных 
действиях.

## 1.1. Общая характеристика предметной области
Предметной областью является деятельность сервиса по формированию 
и отслеживанию полезных привычек. Привычка характеризуется 
периодичностью выполнения (ежедневно, еженедельно). Ценность для 
пользователя определяется регулярностью и непрерывностью выполнения 
привычки. Система хранит факты выполнения, анализ серии (количество 
периодов подряд, когда привычка выполнялась без пропусков), фиксирует 
пропуски.

Деятельность сервиса включает регистрацию пользователей, ведение 
администратором справочника типовых привычек с рекомендуемыми 
параметрами, создание пользователем собственных привычек с указанием 
периодичности, категории и напоминаний, анализ прогресса в виде календаря 
и графиков, отслеживание пропусков с информированием пользователя, 
формирование сводной отчётности. Серверная часть на Spring обеспечивает 
бизнес-логику и предоставляет API для мобильного Android-клиента.

## 1.2. Стейкхолдеры (заинтересованные лица)
На основе анализа предметной области и требований к системе были 
выделены следующие группы стейкхолдеров:

Внутренние стейкхолдеры:

1. Зарегистрированный пользователь:
Интересы: создание собственных привычек; удобная ежедневная отметка о 
выполнении; наглядная статистика прогресса в виде календаря и графиков; 
получение напоминаний о необходимости выполнить привычку; получение 
сводных отчётов в формате Excel/PDF.
Проблемы: сложно самостоятельно контролировать регулярность выполнения 
привычек; пропуски остаются незамеченными без внешней системы 
уведомлений; отсутствует наглядная картина прогресса.
Ожидания: единый сервис, где можно завести привычку, отмечать её 
выполнение, видеть статистику и серии, получать e-mail-напоминания и 
выгружать отчёты о прогрессе.

2. Администратор (управляющий сервисом):
Интересы: 
управление пользователями (просмотр, редактирование, 
блокировка); ведение справочника типовых привычек с рекомендуемыми 
параметрами; получение сводных отчётов по системе на основе данных из БД.
Проблемы: сложно отслеживать активность пользователей и получать 
оперативную сводную информацию.
Ожидания: кабинет администратора с возможностью добавления и 
редактирования данных; формирование отчётов на основе информации из БД; 
разграничение прав доступа.

Внешние стейкхолдеры:

3. Владелец сервиса (заказчик):
Интересы: контроль показателей работы сервиса, оценка вовлечённости 
пользователей, понимание структуры спроса на типовые привычки и 
категории.
Проблемы: формирование отчётности занимает много времени; сложно 
оценить, какие привычки и категории наиболее востребованы; нет 
инструментов для объективной оценки активности пользователей.
Ожидания: сводные отчёты по пользователям, привычкам и выполнению; 
аналитика по популярности типовых привычек и категорий; возможность 
оценивать динамику выполнения и пропусков.

Ключевыми пользователями системы, на автоматизацию задач которых 
будет направлена основная функциональность, являются зарегистрированный 
пользователь и администратор.

## 1.3. Ключевые сущности (объекты)
Основными объектами предметной области, информация о которых 
будет храниться в базе данных, являются:

1) Пользователь – зарегистрированный пользователь системы. Содержит 
учётные данные (email, имя пользователя, пароль в виде хэша), 
персональную информацию (имя, фамилия), дату регистрации, признак 
активности и ссылку на роль. Роль вынесена в отдельный справочник и 
определяет права доступа: обычный пользователь или администратор.

2) Роль – справочник ролей пользователей. Содержит название роли 
(USER, ADMIN) и используется для разграничения доступа к 
функционалу системы: администратор управляет справочниками и пользователями, обычный пользователь работает со своими 
привычками и видит свою статистику.

3) Категория привычки – справочник категорий (спорт, здоровье, учёба, 
работа и т.д.). Содержит название и признак системной категории. 
Системные категории создаются администратором и доступны всем 
пользователям; пользовательские категории создаются самим 
пользователем и видны только ему.

4) Привычка – сущность, описывающая привычку, доступную в системе. 
Содержит название, описание, ссылку на категорию, целевую частоту 
выполнения (DAILY – ежедневно, WEEKLY – еженедельно), целевое 
количество выполнений за период, дни недели и ссылку на создателя. 
Если привычка создана администратором, она является шаблонной и 
доступна всем пользователям для начала освоения; если создана 
обычным пользователем – доступна только ему.

5) Этап освоения – связующая сущность между пользователем и 
привычкой. Фиксирует факт начала освоения привычки конкретным 
пользователем и отслеживает прогресс. Содержит дату начала, дату 
завершения, статус освоения (ACTIVE – в процессе, COMPLETED – 
освоена, ABANDONED – брошена), текущую и максимальную серию по 
отметкам, текущую и максимальную серию периодов, количество 
пропусков подряд, настройки напоминания (флаг включения, время, дни 
недели, дата последней отправки напоминания). У пользователя не 
может быть более одного активного этапа для одной привычки; после 
завершения или отказа от этапа пользователь может начать привычку 
заново, создав новый этап с сохранением истории предыдущих попыток.

6) Выполнение привычки – сущность, фиксирующая факт отметки 
выполнения привычки. Содержит ссылку на этап освоения, дату 
выполнения (день, к которому относится отметка), точное время 
отметки, статус (DONE – выполнено, SKIPPED – пропущено) и заметку. 
Каждая отметка хранится отдельной записью, что позволяет фиксировать привычки, требующие нескольких выполнений в день 
(например, «выпить 8 стаканов воды»). Количество отметок за день 
сравнивается с целевым количеством выполнений привычки; при 
достижении цели дальнейшие отметки за этот день блокируются.

В рамках разрабатываемого приложения будут автоматизированы 
следующие ключевые бизнес-процессы:

1) Регистрация и аутентификация. Пользователь регистрируется в системе, 
указывая email, имя пользователя, пароль и персональные данные. После 
регистрации пользователю назначается роль USER. Вход выполняется 
по email и паролю; Администратор (ADMIN) получает доступ к 
расширенному функционалу управления системой.

2) Создание и настройка привычки. Пользователь создаёт собственную 
привычку, указывая название, описание, категорию (из системных или 
собственных), частоту выполнения, целевое количество выполнений за 
период и дни недели (при необходимости). Созданная привычка 
является личной и доступна только её создателю. Администратор 
создаёт шаблонные привычки с рекомендуемыми параметрами, которые 
видны всем пользователям и доступны для начала освоения.

3) Начало освоения привычки. Пользователь выбирает привычку (свою 
или шаблонную) и начинает её осваивать. Система создаёт этап 
освоения со статусом ACTIVE, фиксирует дату начала и 
инициализирует счётчики серий и пропусков. Система не позволяет 
начать привычку повторно, пока текущий этап активен; при этом 
пользователь может завершить или бросить текущий этап и начать 
новый с сохранением истории предыдущих попыток.

4) Отметка выполнения. Пользователь отмечает выполнение привычки, 
система сохраняет отметку с указанием даты и времени. Количество 
отметок за день сравнивается с целевым значением привычки: при 
достижении цели дальнейшие отметки за этот день блокируются, о чём 
пользователь получает уведомление. Серии и счётчики пропусков пересчитываются фоновым процессом: серия по отметкам учитывает 
каждую отметку, серия периодов засчитывается только при достижении 
целевого количества за период (DAILY – день, WEEKLY – неделя); при 
незасчитанном периоде счётчик пропусков подряд увеличивается, при 
засчитанном – сбрасывается.

5) Просмотр статистики и прогресса. Пользователь просматривает список 
своих привычек с фильтрацией по частоте и категориям, анализирует 
прогресс в виде календаря и графиков, просматривает историю 
выполнения по каждому этапу, текущие и максимальные серии и 
количество пропусков подряд.

6) Напоминания. Пользователь настраивает напоминание для этапа 
освоения: включает его, указывает время и (при необходимости) дни 
недели. Фоновый процесс регулярно проверяет активные этапы с 
включёнными напоминаниями и отправляет пользователю e-mail в 
заданное время, не допуская повторной отправки в течение одного дня.

7) Формирование отчётности. Пользователь формирует отчёты о своём 
прогрессе; администратор – сводные отчёты по пользователям, 
привычкам и категориям. Отчёты формируются на основе данных из 
базы и выгружаются в формате Excel.

8) Управление справочниками и пользователями (администратор). 
Администратор управляет пользователями, системными категориями и 
шаблонными привычками, просматривает сводные отчёты по системе.

Таким образом, организация работы сервиса характеризуется отслеживанием 
выполнения привычек, достоверностью данных о пропусках и аналитикой 
статистики. Разработка серверной части на Spring с базой данных PostgreSQL 
позволит централизовать хранение данных, автоматизировать отслеживание 
пропусков и серий выполнения, обеспечить разграничение доступа по ролям, 
формирование сводных отчётов и отправку e-mail-уведомлений. Внедрение 
такой системы приведёт к повышению регулярности выполнения привычек 
пользователями, оптимизации работы администратора и росту 
эффективности сервиса.
